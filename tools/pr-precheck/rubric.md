# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | The diff's changed files and hunks read against the accepted plan's scope, files to change, and approach, plus any Deviations recorded in the plan. | Pass if every behavior change in the diff is covered by the plan or by a recorded Deviation, and nothing the plan committed to is silently missing. Planned work that was dropped or changed passes only when a Deviation or the PR description says so and why. Fail if the diff does more or less than the plan with no recorded explanation. | required |
| Description matches diff | The PR title and description read against the actual diff and commits. | Pass if every change the description claims is present in the diff, every material change in the diff is described, and any claim of fidelity to the plan ("implements the plan as posted", "no other changes") is true of the diff. Fail if the description claims something the diff does not do, omits a material change the diff makes, or claims a fidelity the diff contradicts. | required |
| Test evidence | The test evidence (test output, commands, before/after results) read against the plan's test plan and against every "tested" or "verified" claim in the PR description. | Pass if the primary bug-fix evidence (the plan's reproduction re-run on the branch's code, for the same scenario the test plan names) is shown as observable output that distinguishes the fixed behavior from the reproduced bug as the plan's test plan defines it. Supporting items (test suite, lint, typecheck, smoke check, negative control) count when the package names the command or check and states a specific result that no other evidence in the package contradicts; they never substitute for the primary evidence. Every testing claim in the description is backed by evidence of one of these two kinds. A test-plan item that was not run passes only when the PR honestly discloses it as not run and why. Fail if the primary evidence is missing, is an assertion with no observable output ("works now", "verified working"), or verifies a different scenario than the plan's repro; or if any testing claim is vague (such as "tests pass" with no command and no specific result), cannot be tied to this change, or is contradicted. | required |
| Repo checks run | The repo's stated test, lint, or build commands (from CONTRIBUTING.md, the PR template, or the repo facts) read against the test evidence. | Pass if, for each check the repo requires, the package names the command (or the template checklist item it answers) and states a specific result on the branch (for example "passes (312 tests)", "clean", "no diff") that no other evidence in the package contradicts, or reports a failure honestly explained as unrelated to this change. Pass if the repo states no required checks. Fail if a required check is not mentioned, is covered only by a vague claim that names neither the command nor the checklist item, or is contradicted by other evidence. | required |
| Diff focus | The diff's hunks read against the change the plan and description describe. | Pass if every hunk serves the described change, so a reviewer can read the diff without separating the change from noise. Fail if the diff carries debris (debug prints, commented-out code, stray or generated files, unrelated formatting or lockfile churn) or unrelated hunks that bury the change. | required |
| Template completeness | The PR description read against every section of the repository PR template. | Pass if every section the template asks for is present and filled with content specific to this PR (a section that genuinely does not apply says so). Fail if a section is missing, left as template placeholder text, or filled with content that does not describe this PR. | required |
| Contribution policy | The PR's branch name, target branch, issue link, and commit/PR conventions read against the repository's stated contribution requirements. Live mode: docs/CONTRIBUTING.md, the PR template, the issue thread, and the applicable house rules in scope.md. Eval mode: the repo-facts and policy information in the bundle. | Pass if the PR meets every contribution requirement the repository explicitly states, including its branch-naming rule (graded against the rule as stated, for example a type prefix such as `fix/`, `docs/`, `feat/`, `test/`, `refactor/`, `perf/`, or `chore/` that fits the change, not against one assumed prefix), its target branch, its issue-link requirement, and one PR per issue. Fail if the PR breaks any explicitly stated requirement. | required |
| AI-use disclosure | Live mode: the PR description's "Notes for Reviewers" section, read against the course requirement that every live PR disclose AI use there (plus any further disclosure rule in docs/CONTRIBUTING.md or the PR template). Eval mode: the PR description read against the AI-use disclosure requirement stated in the bundle's repo facts and policy information. | Live mode: pass if "Notes for Reviewers" contains a disclosure that states, in the student's own words, how AI was used on this change, and it meets any further repository disclosure rule; the course requirement applies even when the repository states no AI policy. Eval mode: pass if the bundle states a disclosure requirement and the PR includes a disclosure that meets it, or if the bundle states no AI policy or disclosure requirement. Fail if a required disclosure is missing, empty, left as placeholder text, or (live) outside "Notes for Reviewers" or not specific to how AI was used on this change. | required |
| Commit hygiene | The branch's commits (messages and the changes each contains). | Pass if each commit message describes the change it contains and the history contains no fix-up noise a reviewer has to untangle ("wip", "oops", reverted experiments). | preferred |

## Verdict rule

Accept only if every required check passes. Reject if any required check
fails or is unclear: an unclear grade means the package does not let the
check be verified, and a PR that cannot be verified from the package is not
ready to submit, so unclear counts as fail. Preferred checks are graded and
reported but never change the verdict.

A check whose requirement the repository does not state (for example, no
required test commands, or in eval mode no AI-use disclosure rule) passes, and its
evidence line names the source that was checked and found silent. This does
not apply to the live-mode AI-use disclosure, which the course always
requires regardless of repository silence. A PR that
honestly discloses a shortfall (dropped plan work recorded as a Deviation, a
test-plan item disclosed as not run) is graded on the disclosure; doing less
than everything is not by itself a reason to reject.
